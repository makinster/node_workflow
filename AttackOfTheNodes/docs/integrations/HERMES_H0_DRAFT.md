**H0 contract, 2026-10-20; repository implementation awaiting owner review.**
The owner authorized the [adapter and spec files](../../integrations/hermes/README.md)
after the decisions recorded in PR #102. The contract below remains the design
baseline; installation and job activation are separate owner actions.
The design was updated against main `f86fbe8` (#98 colours and #99 quiet End merged) and
[coordination proposal §5.1](../AI_COORDINATION_PROPOSAL.md#51-short-workflows-aotn-run-is-the-cron-script).
The initial specification preceded the owner decisions in #102. The
wrapper/adapter below describes the external script interface, now versioned
in the repository but not installed into Hermes. The two workflow specs use existing
nodes and `aotn build`; they need no engine changes or Stash entries.

H0 proves a short unattended run can produce a message, stay silent, or fail
with its exit status intact. It does not install scripts, create cron jobs,
send Telegram messages, or claim a delivery receipt. Hermes's behavior below
is an assumption from the dated inspection in proposal §3, not a fresh Hermes
installation check. Recheck it before enabling a job.

## 1. Files and execution contract

| `/home/makin/.hermes/scripts/aotn-h1-heartbeat.sh` | Scheduled entry for workflow `h1-heartbeat` |
| `/home/makin/.hermes/scripts/aotn-h2-http-watchdog.sh` | Scheduled entry for workflow `h2-http-watchdog` |
| `/home/makin/.hermes/scripts/_aotn_common.sh` | Shared Bash function `aotn_cron_run`; never scheduled |
| `/home/makin/.hermes/scripts/_aotn_run.py` | Proposed output/exit adapter, standard library only; never scheduled |
| `/home/makin/.local/share/aotn-cron/` | Separate AOTN data directory: saved workflows, settings, run records and outputs |
| `/home/makin/src/node_workflow/` | Authoritative project root |
| `/home/makin/src/node_workflow/.venv/bin/python` | Absolute AOTN interpreter; ignore Hermes's venv on PATH |

One entry file per workflow, with the same body (illustrative; dependencies
are not provided in this draft):

```bash
#!/usr/bin/env bash
set -euo pipefail
source /home/makin/.hermes/scripts/_aotn_common.sh
aotn_cron_run "$0"
```

The shared function derives the workflow from the entry file's basename:
`aotn-<slug>.sh` maps to the **exact saved name** `<slug>`. Accept only
`[a-z0-9][a-z0-9_-]*`; reject an empty slug or a different suffix. Accept no
wrapper arguments. Quote paths/names and construct argv arrays; never use
`eval`, a shell command assembled from workflow data, or a basename as a
filesystem path. Renaming/copying a wrapper selects an existing workflow;
it does not build or copy that workflow. Build once into the separate data
directory first; editing a definition later requires deliberate replacement,
since `aotn build` refuses duplicate names.

`aotn_cron_run` changes to the project root and `exec`s the absolute AOTN
interpreter with `_aotn_run.py`. Proposed adapter arguments are
`--workflow-slug <slug>`, `--project-root <absolute root>`,
`--data-dir <absolute cron directory>` and `--python <absolute interpreter>`.
The deadline, stream limits and directive policy below are fixed H0 defaults,
not workflow-controlled settings. The adapter starts this child argv (the timestamp is generated by the adapter,
not accepted from external text):

```text
/home/makin/src/node_workflow/.venv/bin/python
/home/makin/src/node_workflow/AttackOfTheNodes/main.py
run <slug> --policy terminate_workflow
--data-dir /home/makin/.local/share/aotn-cron
--input checked_at=<UTC ISO-8601 timestamp ending in Z>
--json
```

Every H0 spec declares `checked_at`. Run with stdin closed, cwd at the project
root, and the explicit data directory set before backend imports. Use the
checkout's `main.py` to avoid an editable install selecting a different tree.
Never use the repository's `AttackOfTheNodes/workflows/` as the cron library.
These are ordinary workflows, not callable Return End workflows.

### Why an adapter instead of direct exec

Direct `exec ... main.py run ...` preserves the exit code but cannot also cap
or escape stdout. A `head` pipeline can mask the exit code or close the pipe
early. This draft refines §5.1: the shell **execs the adapter**, and the adapter
runs AOTN as a subprocess and preserves its natural exit status. No AOTN
module is imported into the adapter process.

Use `--json` to obtain the structured `run_id`, `outputs`, `values`,
`final_state`, and `exit_code`. Do not scrape human stderr for a run ID or
select the newest history file (overlapping jobs make that ambiguous).
On a normal exit, render each output as the current text CLI does: a dict
with `value` uses that value; other dicts/lists use JSON; scalars use text.
Render any named `values` as `name = value`, using JSON for collections.
H1/H2 have no named return values. Each terminal `end_node` has `record_line: false` (the Parameters option
"Add a line to the output" is off, merged in #99). It stops the branch
without adding an `[END] ...` line. An End with the option omitted still
records its completion line for compatibility with existing workflows. Validate the report shape and that its
`exit_code` matches the process result; absence of JSON on a nonzero
pre-start failure is expected, not a second adapter error.

### Output, limits and exits

Proposed adapter rules, to be implemented and tested after owner review:

1. Drain stdout and stderr concurrently. Keep at most 1 MiB of stdout for
   parsing the report and 64 KiB of stderr diagnostics. Excess stderr is
   drained/discarded with a truncation notice. Oversized stdout is an adapter
   failure: stop the child, print a bounded diagnostic to stderr, exit 70.
   Do not treat a report prefix as a complete successful run.
2. On exit 0, emit only rendered outputs/values on stdout. No banner,
   status, JSON envelope, or successful-run ID line. With no outputs/values,
   write **zero bytes** to stdout, including no newline. Diagnostics stay on
   stderr; a healthy silent watchdog must not become a message.
3. On a natural nonzero AOTN exit, emit no stdout and preserve that numeric
   exit code. Put escaped/capped child diagnostics on stderr, adding a
   concise failure summary and the report's run ID when available. This
   leaves Hermes's failure-alert path in charge, without a second ordinary
   notification. Before-start failures may have no run ID.
4. For both message and diagnostic text, escape every case variant of `[SILENT]`
   recognized by Hermes's uppercase-normalized gate (including `[silent]`
   and `[SiLeNt]`), replacing the marker's brackets with fullwidth brackets and every literal `MEDIA:` with `MEDIA：`.
   Prefix `| ` only to a line that, after leading spaces, starts with `{`,
   so a final JSON-looking line cannot become a `wakeAgent` directive.
   Ordinary lines are sent unchanged (owner, 2026-10-20: plain messages such
   as the heartbeat must not start with `| `). Apply this to the final
   combined text, not each stream fragment. Empty successful output stays empty. H0 offers no
   directive-passthrough switch; attachment/directive policy belongs to a
   later reviewed integration.
5. Cap each outgoing stream at **3,500 UTF-16 code units**, including line
   prefixes, newlines and any truncation tail. Count after escaping; do not
   split a supplementary Unicode character. When truncating stdout, reserve
   space for `| …truncated; see run <run_id>` within the same budget. Use
   `run unavailable` only for diagnostics that lack a report. A run's full
   output stays in AOTN's isolated run records; it is not a Telegram receipt.
6. Use a proposed **100-second** child deadline, including graceful cleanup.
   Start the child in its own process group. At 95 seconds, signal SIGINT to
   that group; at 100 seconds kill/reap it if it has not finished cleanup.
   Report the deadline as exit 124 with a bounded diagnostic. For an
   external SIGINT or SIGTERM, request graceful child shutdown using SIGINT
   (AOTN handles SIGINT; forwarding SIGTERM directly skips finalization).
   Allow up to five seconds, then kill/reap if needed; retain the adapter's
   external-signal exit status, 130 or 143 respectively.
   Natural AOTN exits (including error exits and 130) retain their codes;
   adapter failures are 70. A child killed by a signal maps to the shell
   convention `128 + signal_number`. Never turn a failure into exit 0 to suppress an
   alert. An inner HTTP timeout is five seconds in H2.
7. Serialize each slug with a nonblocking lock under the cron data directory.
   Hold it through child cleanup. An overlapping tick exits 75 on stderr,
   with no stdout; it does not start another run. Different slugs may run
   independently. Do not claim global exactly-once execution or notification
   deduplication; H0 has neither a persistent dedupe store nor an outbox.

AOTN's natural exits include 0 (success), 1 (finished with unhandled errors),
2 (failed), 3 (invalid/could not start), 4 (not found), 5 (bad contract inputs)
and 130 (interrupted); preserve the actual process code, including usage
errors. Relevant implementations are [the run CLI](../../aotn_cli.py) and
[RunResult](../../backend/run_service.py). On success, ordinary CLI output
matches the rendered report before the adapter's escaping/prefix/cap.

The 3,500-unit budget applies to text handed to Hermes. Hermes's own wrapping
may add text; verify the final size/framing with the chosen configuration.
Do not silently change the gateway's global `cron.wrap_response` or timeout.

## 2. H1: heartbeat (`h1-heartbeat.json`)

Copy this complete `aotn-workflow/1` spec to a scratch file outside the repo's
workflow directory. Start emits the timestamp supplied by the wrapper; Text
Output supports `{input}`, not a `{date}` placeholder.

```json
{
  "format": "aotn-workflow/1",
  "name": "h1-heartbeat",
  "nodes": {
    "start": {"type": "start_node", "config": {"rows": [
      {"name": "checked_at", "type": "string", "required": true, "to": "Downstream"}
    ]}},
    "announce": {"type": "text_output_node", "alias": "Heartbeat", "config": {
      "input_source": "Upstream payload", "label": "Heartbeat",
      "template": "AOTN alive · {input}", "request_user_input": false
    }},
    "end": {"type": "end_node", "alias": "Finish quietly", "config": {"record_line": false}}
  },
  "connections": [
    {"from": "start.default", "to": "announce.input"},
    {"from": "announce.default", "to": "end.input"}
  ]
}
```

With `checked_at=2026-10-20T12:00:00Z`, raw text CLI stdout is exactly:

```text
[Heartbeat] AOTN alive · 2026-10-20T12:00:00Z
```

The adapter would hand Hermes that line unchanged, exit 0. This
checks that no status/debug line leaks into successful message output. The
ordinary CLI's completion summary is on stderr; the JSON mode report is
consumed by the adapter, never sent as the message.

## 3. H2: HTTP watchdog (`h2-http-watchdog.json`)

The example checks an operator-selected local health endpoint with GET.
Replace its URL and expected body deliberately before building. It follows
urllib's redirects; this is a **response-body health check**, not a strict
HTTP-status/TLS/security monitor. Success means the stripped response is
exactly lowercase `ok`. No request body, authentication, AI node or prompt.
A healthy response takes the quiet End path (`record_line: false`). An unexpected successful body
emits fixed text. Timeout, network and HTTP-status failures are handled by
an inline Error Mux and emit a different fixed message with exit 0. Other
failures stay unhandled and reach Hermes's failure-alert path. Neither
message includes the remote response body or error details.

```json
{
  "format": "aotn-workflow/1",
  "name": "h2-http-watchdog",
  "nodes": {
    "start": {"type": "start_node", "config": {"rows": [
      {"name": "checked_at", "type": "string", "required": true, "to": "Downstream"}
    ]}},
    "fetch": {"type": "http_request_node", "alias": "Check health", "config": {
      "url": "http://127.0.0.1:8765/health", "method": "GET",
      "response_mode": "text", "timeout_seconds": 5
    }},
    "catch": {"type": "error_mux_node", "alias": "Known check failures", "config": {
      "routes": [{"id": "offline", "label": "Unavailable", "codes": ["network", "timeout", "http_status"]}],
      "unmatched_route": false
    }},
    "strip": {"type": "text_transform_node", "config": {"operation": "strip"}},
    "unhealthy": {"type": "conditional_node", "alias": "Body differs from ok", "config": {
      "condition_type": "not_equals", "left_value_source": "input", "right_value": "ok"
    }},
    "alert": {"type": "text_output_node", "alias": "Unexpected health", "config": {
      "input_source": "Upstream payload", "label": "Watchdog",
      "template": "Health check returned an unexpected body. Inspect the endpoint and run record.",
      "request_user_input": false
    }},
    "offline": {"type": "text_output_node", "alias": "Unavailable health", "config": {
      "input_source": "Upstream payload", "label": "Watchdog",
      "template": "Health endpoint unavailable (network, timeout or HTTP error). Inspect the run record.",
      "request_user_input": false
    }},
    "end_ok": {"type": "end_node", "alias": "Healthy: no message", "config": {"record_line": false}},
    "end_alert": {"type": "end_node", "alias": "Finish alert path", "config": {"record_line": false}},
    "end_offline": {"type": "end_node", "alias": "Finish unavailable path", "config": {"record_line": false}}
  },
  "connections": [
    {"from": "start.default", "to": "fetch.input"},
    {"from": "fetch.default", "to": "catch.input"},
    {"from": "catch.default", "to": "strip.input"},
    {"from": "catch.offline", "to": "offline.input"},
    {"from": "strip.default", "to": "unhealthy.input"},
    {"from": "unhealthy.true", "to": "alert.input"},
    {"from": "unhealthy.false", "to": "end_ok.input"},
    {"from": "alert.default", "to": "end_alert.input"},
    {"from": "offline.default", "to": "end_offline.input"}
  ]
}
```

A known HTTP failure is a **handled error**: stderr may log it while the run
exits 0 and sends its fixed message. Treating every stderr line as a failed
run would break this distinction. An unexpected body does not spend tokens,
run a fix, or request human input. H0 has no cross-tick suppression: every
unhealthy tick can notify. Choose a conservative schedule during trial.
File-age/disk-space checks require additional capabilities and are not
claimed by this HTTP-only H2 example.

## 4. Build/run review procedure

These commands are for a disposable data directory and extracted specs, using
this worktree's `main.py`; they do not install anything into Hermes. From the
repository root (substitute the actual checkout root for a future install):

```bash
h0_scratch=$(mktemp -d /tmp/aotn-h0.XXXXXX)
# Save the two JSON blocks above as $h0_scratch/h1-heartbeat.json and
# $h0_scratch/h2-http-watchdog.json before continuing.
/home/makin/src/node_workflow/.venv/bin/python AttackOfTheNodes/main.py build "$h0_scratch/h1-heartbeat.json" --check --data-dir "$h0_scratch/data"
/home/makin/src/node_workflow/.venv/bin/python AttackOfTheNodes/main.py build "$h0_scratch/h2-http-watchdog.json" --check --data-dir "$h0_scratch/data"
/home/makin/src/node_workflow/.venv/bin/python AttackOfTheNodes/main.py build "$h0_scratch/h1-heartbeat.json" --data-dir "$h0_scratch/data"
/home/makin/src/node_workflow/.venv/bin/python AttackOfTheNodes/main.py build "$h0_scratch/h2-http-watchdog.json" --data-dir "$h0_scratch/data"
/home/makin/src/node_workflow/.venv/bin/python AttackOfTheNodes/main.py run h1-heartbeat --policy terminate_workflow --data-dir "$h0_scratch/data" --input checked_at=2026-10-20T12:00:00Z
/home/makin/src/node_workflow/.venv/bin/python AttackOfTheNodes/main.py run h2-http-watchdog --policy terminate_workflow --data-dir "$h0_scratch/data" --input checked_at=2026-10-20T12:00:00Z --json
```

The required timestamp without a stored default can produce a validation
warning; the adapter supplies it on every run. Missing it fails before the
run with exit 5. `--check` does not run nodes or save a workflow. A plain
HTTP file server is not automatically a health endpoint; provide a fixture
that returns the chosen body/status, or change the URL to a service the
owner intends to monitor. During review, use a loopback fixture on an unused
port and change only the scratch copy's URL. No public network is needed.

| Case | Expected AOTN/adapter behavior | Hermes outcome to verify later |
|---|---|---|
| H1 normal | Exit 0; one timestamped output; summary stays on stderr | One message, no agent invocation |
| H2 body `ok` or ` ok\n` | Exit 0; outputs empty; adapter stdout zero bytes | No message |
| H2 body `degraded` | Exit 0; exactly one fixed unexpected-body output | One ordinary message |
| H2 HTTP 503, refused connection or timeout | Exit 0; handled error; exactly one fixed unavailable output | One ordinary message, not cron-failed alert |
| Forced unhandled error | In a scratch H1 spec replace `announce` with `error_node`, config `{"message":"H0 deliberate failure","error_mode":"fail"}`; use a fresh data directory to avoid duplicate names; nonzero exit is preserved | One cron-failed alert |
| Missing timestamp / unknown saved name | Exit 5 / 4, no successful message | Failure alert with bounded diagnostics |
| Empty report outputs, stderr has completion text | Stdout stays empty; stderr does not become the message | No success notification |
| Oversized/malformed JSON report | Stop/reap if needed; adapter exit 70; no success message | Failure alert |
| Long output with emoji | Escaped/prefixed text + run-ID tail fits 3,500 UTF-16 units | No accidental multi-part flood |
| Outside text contains directives | Literal `[SILENT]`, `MEDIA:` and a final `{"wakeAgent":false}` line are neutralized, including in error diagnostics | No suppression, attachment, or agent-control directive |
| Deadline / overlap / external stop | 124 / 75 / 130 or 143; child reaped, no success output | Failure/stop visible; no orphan run |

## 5. Later activation and review decisions

After the owner approves implementation, build the reviewed definitions into
`/home/makin/.local/share/aotn-cron/` and install the adapter/shared function
and the two entry files. Creating a Hermes job is a separate action. Proposed
trial job properties are `no_agent: true`, one script basename per job,
explicit destination alias, and a five-minute cadence; do not invent a cron
CLI flag or write Hermes's internal job database. Reverify the installed
supported job-creation interface and destination alias then.

Confirm that scripts are resolved inside `$HERMES_HOME/scripts`, cwd/PATH
behave as assumed, empty stdout is silent, nonzero exits alert, and the
configured global Hermes script timeout leaves at least 20 seconds beyond
the adapter's 100-second total budget. Check final Telegram framing/size
and no-agent execution with the owner. A stdout handoff supplies neither
a Telegram message ID nor a delivery result. Delivery reconciliation,
outbox/shared-folder schemas, durable dedupe, AI steps, Stash entries as inputs and
engine changes remain later tasks.

Review choices in this draft: the adapter refinement of direct exec; `--json`
as its stable CLI seam; filename slugs; the separate data-directory path;
always escaping directives; the proposed caps/deadline/overlap behavior;
and the HTTP-only H2 semantics. These do not approve the proposal's other
priorities or authorize live notifications.
